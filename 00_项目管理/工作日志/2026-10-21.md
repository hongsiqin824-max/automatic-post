## 进展
- 17:17 用户贴图首页 500。进程 89867 活着，`web-stderr.log` 从 **13:43** 起全是 `authorization denied`，停了 3.5 小时。先 `kickstart` 恢复（PID 74275）。
- 昨天给 `com.apple.python3` 加的完全磁盘访问权限仍在（auth=2）、进程也是加权限后起的 → 加权限这条路证明无效。用户否决「把 DB 挪出桌面」，要求查原因。
- **排除法**（本终端能做的）：
  - 句柄耗尽实验 → 报「unable to open database file」，不是这个错。
  - `chmod 000` / `chflags uchg` → 报别的或静默只读，不是。
  - `sandbox-exec` 模拟拒绝访问桌面 → **一模一样的 `DatabaseError: authorization denied`**。定性：系统层 sandbox/TCC 拒绝 `open()`。
  - 进程签名 CS_VALID 在、CS_KILL 在（签名坏了会被杀而不是被拒）、责任 pid 是自己、TCC 存的 requirement `identifier "com.apple.python3" and anchor apple` 与静态二进制匹配。全都对，但就是被拒。
  - 本终端 `log show` 任何时段都 0 行 → 系统日志读不到，需要 root。
- 让用户在系统终端 `sudo log show` 导出 13:41–13:44 的 tccd 日志到 `~/Desktop/tcc_1021.log`（3255 行）。读到判决：
  ```
  AUTHREQ_ATTRIBUTION: responsible={identifier=com.apple.dt.xcode_select.tool-shim-public, pid=89867, responsible_path=/usr/bin/git, binary_path=.../Python.app/Contents/MacOS/Python}
  AUTHREQ_SUBJECT: subject=/usr/bin/git
  Platform binary prompting is 'Deny' because: is Platform Binary
  AUTHREQ_RESULT: authValue=0, authReason=5
  ```
- **根因**：plist 写的 `/usr/bin/python3` 是 Xcode 工具垫片，和 `/usr/bin/git` 是同一个 inode 的硬链接（`ls -i` 两者都是 1152921500312571585）。TCC 按责任进程路径查表，inode 反查路径拿到的是最近被用过的名字——有人一跑 git（我提交、Trae git 插件刷新），名字从 `/usr/bin/python3`（表里有）翻成 `/usr/bin/git`（表里没有）→ 静默拒绝到进程重启。三次事故都在有 git 操作的工作时段、都要跑一天才出、重启即好、给真 Python 加权限无效——全部解释通。
- **根治**：plist `ProgramArguments` 改为真二进制 `/Library/Developer/CommandLineTools/Library/Frameworks/Python3.framework/Versions/3.9/Resources/Python.app/Contents/MacOS/Python`（验证过同版本 3.9.6、flask/httpx/pymysql 可导入、签名 `com.apple.python3`，昨天加的 FDA 正好对它生效）。原 plist 备份 `.bak_20261021`。`bootout` + `bootstrap` 重载，PID 95841，PPID 1，9 线程，HTTP 200。
- 验证：故意跑 `git status/log/--version`，35 秒后 0 报错、DB 正常写。
- 顺带：用 `dqd-bigdata-sr` 技能查了足球标签——名字就叫「足球」的通用频道标签是 **12039035**（OtherChannel），另有「国际足球」12068979、「中国足球」12078556。还拉了当前赛季 10–24 队的正规联赛清单约 200 个（项目只用了 33 个），用户暂未指定要加哪个。

## 踩过的坑
- **`/usr/bin/python3` 不是 Python**，是和 git 共用 inode 的垫片。launchd 托管的服务一律写真路径。
- **TCC 判决看的身份可以和你以为的完全不同**：`binary_path` 是真 Python，`responsible_path`/`subject` 却是 `/usr/bin/git`。不读 tccd 日志根本猜不到。
- **Trae 里的终端读不到系统统一日志**（`log show` 永远 0 行，不报错）。要查 tccd/sandboxd/kernel 必须在系统终端 `sudo log show`。
- 排除法比猜快：三个小实验（fd 耗尽 / 权限位 / sandbox-exec）十分钟内把错误定性到「系统层拒绝」，避免再在代码里找 bug。
- `codesign -v +pid` 对 Python 进程一律报 invalid signature，是工具局限，不能作为判据；用 `csops` 读 CS 标志才准。
